### N64Recomp — important notes

- **CMake target is `N64RecompCLI`**, not `N64Recomp` (which is the static library)
- Officially, N64Recomp still says: *"the only way to provide the required metadata is by passing an elf file"*
- The ROM-only mode (symbols.toml without ELF) is **planned但 not officially shipped** — issue #13 tracks it
- Thiago Lira adapted his config to use ROM + symbols.toml, but this likely required custom patches
- **For WPJ2: use the decomp's ELF** (generated by `LLONSIT-glitch/wonder` `make`) — standard path, no patches needed

### RT64 — microcode support

RT64 supports: `gspFast3D`, `gspF3D`, `gspF3DEX`, `gspF3DEX2`, `gspS2DEX`
If WPJ2 uses a custom ucode (unlikely for 1996), RT64 may need patches. See [Risks](06-risks.md) R1.

### RSPRecomp — aspMain IMEM base

**Critical: SDK 2.0 aspMain mounts at IMEM `0x04001080`, NOT `0x04001000`.**

This was Thiago's most expensive discovery (commit 75e2080a, ~$7.65). All documentation assumes 0x1000. Using 0x1000 misroutes all jumps by -0x80 bytes.

```toml
# aspMain.j1.rsp.toml
[rsp]
imem_base = 0x04001080  # CRITICAL — not 0x04001000
```

## Decompilation Project (primary symbol source)

**Repo:** [LLONSIT-glitch/wonder](https://github.com/LLONSIT-glitch/wonder)
- Standard N64 decomp toolchain (make, binutils-mips, python3)
- Builds matching ROM: `wonderprojectj2.jp.z64`
- Provides: ELF with named symbols, sections, function addresses
- **This replaces the need for Ghidra-based symbol extraction**

Usage:
```bash
git clone https://github.com/LLONSIT-glitch/wonder.git
cd wonder
# Copy ROM as baserom.jp.z64
cp /path/to/wpj2.j1.z64 baserom.jp.z64
make extract
make  # Builds ELF with all symbols
```

## CMake Best Practices (learned from Thiago)

```cmake
# CRITICAL: hidden visibility on recompiled target
set_target_properties(wpj2_recompiled PROPERTIES
    CXX_VISIBILITY_PRESET hidden
    POSITION_INDEPENDENT_CODE ON
)

# Use N64RecompCLI, not N64Recomp
# N64Recomp = static library
# N64RecompCLI = actual executable
```

Flags:
- `-fvisibility=hidden` — prevents game's `send` symbol from colliding with libc `send(2)`
- `-fno-strict-aliasing` — MIPS recompiled code breaks strict aliasing
- Use `g++` on Linux (clang + libstdc++ 22.04 breaks u8string)
